# ユビキタス言語（用語集）

> ステータス: ドラフト（2026-10-05）
> コード上の識別子は「英語名」列に揃える。用語を追加・変更した場合はコードと本書を同時に更新する。

## Task Management コンテキスト

| 用語               | 英語名            | 種別           | 説明                                                                                                                                                                      |
| ------------------ | ----------------- | -------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| タスク             | `Task`            | 集約ルート     | 利用者がやること・やりたいこと。状態・期限・優先度を持つ                                                                                                                  |
| タスク ID          | `TaskId`          | 値オブジェクト | クライアントで生成する UUIDv7。オフライン作成時も即時に確定する                                                                                                           |
| タイトル           | `TaskTitle`       | 値オブジェクト | 1 文字以上の文字列（上限は実装時に決定）                                                                                                                                  |
| 説明文             | `TaskDescription` | 値オブジェクト | タスクの説明（Markdown）。空文字は説明なし。20,000 文字まで。末尾の空白・改行は取り除く                                                                                   |
| 状態               | `TaskStatus`      | 値オブジェクト | `todo`（未着手）/ `doing`（進行中）/ `done`（完了）/ `canceled`（中止）                                                                                                   |
| 期限               | `DueDate`         | 値オブジェクト | 日付、または日時。任意                                                                                                                                                    |
| 優先度             | `Priority`        | 値オブジェクト | `high` / `medium` / `low`。未指定時は `medium`                                                                                                                            |
| ストーリーポイント | `StoryPoint`      | 値オブジェクト | タスクの大きさの見積もり。目盛り（`STORY_POINT_SCALE`）の値のみ。既定の目盛りはフィボナッチ数列 1・2・3・5・8・13、未指定時は 1。将来は設定で目盛りを変更できるようにする |
| 所有者             | `OwnerId`         | 値オブジェクト | タスクを所有する利用者の ID。全集約が保持する                                                                                                                             |
| 完了日時           | `completedAt`     | 属性           | 完了したときに記録し、再開すると消える。実績の集計に使う。導入前に完了したタスクは記録なし                                                                                |
| 状態の履歴         | `statusHistory`   | 属性           | 状態が変わった記録（状態と日時。古い順、最大 100 件）。登録時の未着手から始まる。導入前に登録したタスクは、その後の変更から記録する                                       |
| タグ ID の集合     | `tagIds`          | 属性           | タスクに付けたタグの ID（重複なし、最大 10 個）。存在しないタグの ID は表示・集計から外す                                                                                 |
| 版                 | `version`         | 属性           | 集約の更新ごとに増える番号。同期時の競合検出に使う                                                                                                                        |

### タグ（ADR 0007）

| 用語     | 英語名     | 種別           | 説明                                                                                                       |
| -------- | ---------- | -------------- | ---------------------------------------------------------------------------------------------------------- |
| タグ     | `Tag`      | 集約ルート     | タスクの分類。名前と色を持つ。タスクとは別の集約で、名前・色の変更はタグを付けたすべてのタスクに反映される |
| タグ ID  | `TagId`    | 値オブジェクト | クライアントで生成する UUIDv7                                                                              |
| タグ名   | `TagName`  | 値オブジェクト | 1〜30 文字。利用者ごとに一意（大文字・小文字、全角・半角の英数字を区別しない）                             |
| タグの色 | `TagColor` | 値オブジェクト | `blue` / `orange` / `aqua` / `yellow` / `magenta` / `green` / `violet` / `red` の 8 色。作成順に割り当てる |

### 状態遷移（初期案）

```
todo ──start──▶ doing ──complete──▶ done
 │                │                   │
 │                └──cancel──┐        └──reopen──▶ todo
 └──complete──▶ done         ▼
 └──cancel────────────▶ canceled ──reopen──▶ todo
```

- `done` / `canceled` からは `reopen` でのみ `todo` に戻れる
- 遷移はすべて `Task` 集約のメソッドを通じて行い、外部から状態を直接書き換えない

### ドメインイベント

| イベント                                                          | 発生契機                                                                                   |
| ----------------------------------------------------------------- | ------------------------------------------------------------------------------------------ |
| `TaskCreated`                                                     | タスク登録                                                                                 |
| `TaskStarted` / `TaskCompleted` / `TaskCanceled` / `TaskReopened` | 状態遷移                                                                                   |
| `TaskRescheduled`                                                 | 期限変更                                                                                   |
| `TaskReprioritized`                                               | 優先度変更                                                                                 |
| `TaskEdited`                                                      | 項目（タイトル・説明文・優先度・期限・ポイント）の編集。値が変わった項目を `fields` に持つ |

## Capture コンテキスト

| 用語         | 英語名                 | 種別           | 説明                                                           |
| ------------ | ---------------------- | -------------- | -------------------------------------------------------------- |
| 下書き       | `TaskDraft`            | 集約ルート     | 入力を受け付けた直後の未解析データ。解析後に `Task` へ確定する |
| 入力原文     | `RawInput`             | 値オブジェクト | キー入力または音声の文字起こし結果                             |
| 入力経路     | `InputSource`          | 値オブジェクト | `keyboard` / `voice`                                           |
| 解析結果     | `ParsedTaskAttributes` | 値オブジェクト | 原文から抽出したタイトル・期限・優先度                         |
| 下書き解析器 | `TaskDraftParser`      | Port           | 原文から解析結果を得るインターフェース。実装は差し替え可能     |

### TaskDraft の状態

`pending`（未解析）→ `parsed`（解析済み）→ `promoted`（Task に確定済み）／ `failed`（解析失敗。原文のまま Task 化も可）

## Insights コンテキスト

| 用語         | 英語名        | 説明                                                                                       |
| ------------ | ------------- | ------------------------------------------------------------------------------------------ |
| 進捗         | `Progress`    | 期間内のタスク状態の分布                                                                   |
| 成果         | `Achievement` | 期間内に完了したタスクの集計                                                               |
| 完了ポイント | —             | 期間内に完了したタスクのストーリーポイントの合計                                           |
| ベロシティ   | —             | 週あたりの完了ポイント。実績画面では今週を除く直近 7 週の平均                              |
| 累積フロー図 | —             | 日ごとの未着手・着手中・完了の件数を積み上げた面グラフ。帯が太るところに作業が溜まっている |

※ Insights は読み取り専用のモデルで、Task 集約を直接参照しない。現在はクライアントのタスク一覧（`TaskDto`）から集計している（`packages/insights`）。週は月曜始まり、日付は端末のタイムゾーンで扱う。

## 同期（横断的関心事）

| 用語           | 英語名          | 説明                                                                                                                                                                          |
| -------------- | --------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 操作           | `TaskCommand`   | 同期で送る操作（`CreateTask` / `ChangeTaskStatus` / `EditTask` / `CreateTag` / `RenameTag` / `RecolorTag` / `DeleteTag`）。サーバーは同じユースケースで再実行する（ADR 0006） |
| 送信待ちの変更 | `PendingChange` | `changeId` と操作の組。Outbox に記録する                                                                                                                                      |
| 変更 ID        | `changeId`      | クライアントで生成する変更の ID。再送時の重複適用を防ぐ                                                                                                                       |
| 実行日時       | `occurredAt`    | クライアントで操作を実行した日時。サーバーとリベースはこの日時で操作を再実行する                                                                                              |
| 送信待ち       | `Outbox`        | ローカルで発生した未送信の変更の置き場                                                                                                                                        |
| 処理結果       | `ChangeResult`  | push した変更ごとの結果。`applied`（適用）または `rejected`（差し戻し）                                                                                                       |
| 差し戻し       | `Rejection`     | サーバー側の検証で拒否された変更。クライアントで利用者に通知する                                                                                                              |
| 変更連番       | `seq`           | サーバーが変更ログに付ける単調増加の番号                                                                                                                                      |
| 同期の変更     | `SyncChange`    | pull で返す変更。種類（`task` / `tag` / `tagDeleted`）を持つ                                                                                                                  |
| 同期カーソル   | `SyncCursor`    | クライアントがサーバーから取得済みの最大 `seq`                                                                                                                                |
