# 0008. AI 清書を Vertex AI 経由の Claude で行い、結果は通常の編集として反映する

- ステータス: 提案
- 日付: 2026-10-09
- 関連: ADR 0004（入力解析を差し替え可能な Port とする）

## コンテキスト

- 登録したタスクを AI で清書したい。対象はタイトル・説明文・期限・優先度・ストーリーポイント・タグ
- 清書は利用者がボタンを押したときだけ実行し、結果で自動的に書き換える。直後に数秒間「元に戻す」を出す
- ボタンは詳細パネル（登録済みのタスク）と入力欄（「AI で清書して登録」）の両方に置く
- オフライン中は清書できないため、オンラインに戻ってから実行する
- Claude は **Google Cloud の Vertex AI 経由** で呼び出す。API キーは発行せず、**Cloud Run に割り当てたサービスアカウントの権限（ADC）** で認証する

## 決定

### 呼び出し

1. 清書は **API サーバー（`apps/api`）だけ** が Vertex AI を呼ぶ。ブラウザから直接は呼ばない
2. SDK は公式の `@anthropic-ai/vertex-sdk`（`AnthropicVertex`）を使う。認証は ADC
   - Cloud Run: 割り当てたサービスアカウント（Vertex AI を呼ぶ権限だけを持たせる）
   - 開発環境: 開発者自身の ADC（`gcloud auth application-default login`）
   - プロジェクト ID とリージョンは環境変数で渡す（リージョンは `global` を推奨）。機密値ではないが `.tf` には直書きせず `tfvars/` に置く
3. 応答は **構造化出力**（`output_config.format` + zod）で受け取り、さらにドメインのルール（タイトルの長さ、ポイントの目盛り、タグの上限など）で検証する
4. 清書は Capture コンテキストの Port（`TaskCleaner`）として定義し、Vertex AI の実装は infrastructure 側に置く（ADR 0004 の方針）
   - Vertex AI の設定（プロジェクト ID）がない環境では、Vertex AI を呼ばない **偽の実装** を使う（開発・テスト用）
5. モデルは **Claude Haiku 5.5**（`claude-haiku-5-5`）。清書は定型的な整形・抽出のため、`effort: "low"` から始め、品質を見て調整する

### 送るデータ（外部送信の範囲）

6. 送るのは **清書する 1 件のタスクの内容だけ** とする
   - タイトル、説明文（先頭から最大 8,000 文字）、期限、優先度、ポイント
   - 既存のタグの名前の一覧（タグを推定するため）
   - 今日の日付とタイムゾーン（「明日」などの表現を解釈するため）
7. 送らないもの: 利用者 ID、タスク・タグの ID、ほかのタスク、端末の情報
8. 送った内容と応答の本文はログに残さない（件数・所要時間・トークン数・エラー種別だけ記録する）

### 反映

9. API は清書の結果を返すだけで、タスクは書き換えない。**クライアントが `EditTask`（ADR 0006）でローカルに反映** し、通常の変更として同期する
   - オフライン対応・競合時の扱いが通常の編集と同じになる
   - 「元に戻す」は、清書前の値で `EditTask` をもう一度実行する
10. 「AI で清書して登録」は、まず通常どおり登録してから清書する。オフライン中は清書の予約だけ記録し、オンラインに戻ったときに実行する
11. **タグ**: 既存のタグから選ぶ。合うタグがなければ、AI が提案した新しいタグ（1 回あたり最大 2 個）を作る。「元に戻す」ではタスクのタグは元に戻すが、作ったタグ自体は残す（不要なら設定画面で削除する）

### 費用と乱用の防止

12. 1 回の出力の上限（`max_tokens`）を設け、利用者ごとに **1 日 50 回** までとする（上限を超えたら 429 を返し、画面で知らせる）
13. 安全上の理由で拒否された場合（`stop_reason: "refusal"`）は、書き換えずに「清書できませんでした」と知らせる。Vertex AI ではサーバー側の自動フォールバック（`fallbacks`）は使えない

## 検討した代替案

| 案                                         | 不採用理由                                                                     |
| ------------------------------------------ | ------------------------------------------------------------------------------ |
| ブラウザから直接 Vertex AI を呼ぶ          | 認証情報をブラウザに渡すことになる                                             |
| サーバーが清書結果でタスクを直接書き換える | オフラインのローカル変更と競合し、同期の仕組み（ADR 0006）と二重になる         |
| Anthropic の API（直接）を使う             | API キーの発行と管理が必要になる。GCP のサービスアカウントで認証を一本化したい |

## 結果

- 良い点: API キーを持たずに済み、権限は IAM で管理できる
- 良い点: 清書結果が通常の編集として扱われるため、同期・競合・取り消しの仕組みを再利用できる
- 悪い点: 清書のたびにタスクの内容が Google Cloud（Vertex AI）上の Claude に送られる
- 留意点: Vertex AI 上の Claude の料金・データの取り扱い（保持・学習への利用の有無）は、着手時点の Google Cloud の公式情報で確認する
- 留意点: Vertex AI で Claude のモデルを使えるようにする設定（Model Garden での有効化）、サービスアカウントへの権限付与は、インフラ整備（Terraform）の際に行う
