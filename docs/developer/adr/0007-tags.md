# 0007. タグを独立した集約とし、同期の対象をタスク以外に広げる

- ステータス: 提案
- 日付: 2026-10-06

## コンテキスト

- タスクにタグを付け、タグごとに実績を集計したい
- タグは登録・編集のときに名前を入力して、その場で作れるようにする（既存のタグは候補として出す）
- 1 つのタスクに複数のタグを付けられる
- タグの色・名前は設定画面で変更でき、変更はそのタグを付けたすべてのタスクに反映される
- オフラインでも使える必要がある（ADR 0002）

## 決定

### ドメイン

1. **`Tag` を Task Management コンテキストの独立した集約** とする
   - `id`（クライアントで生成する UUIDv7）、`name`、`color`、`version`
   - `name`: 前後の空白を除いて 1〜30 文字。利用者ごとに一意（大文字・小文字、全角・半角の英数字を区別しない）
   - `color`: 決められた 8 色の中から選ぶ（`blue` / `orange` / `aqua` / `yellow` / `magenta` / `green` / `violet` / `red`）。作成時は、作成した順に 8 色を順番に割り当てる
2. **タスクはタグの ID の集合（`tagIds`）を持つ**（最大 10 個）
   - 登録（`CreateTask`）と編集（`EditTask`）で指定する。`EditTask` では集合全体を置き換える
   - タスクはタグが存在するかを検証しない。存在しない ID（削除済み・同期で差し戻されたもの）は、表示と集計から外す
3. タグの操作: `CreateTag` / `RenameTag` / `RecolorTag` / `DeleteTag`
   - 削除は物理削除とし、タスクの `tagIds` は書き換えない（上記のとおり表示・集計から外れる）

### 同期

4. **変更ログの対象を広げる**。pull で返す変更に種類を持たせる
   - `{ seq, kind: "task", task }` / `{ seq, kind: "tag", tag }` / `{ seq, kind: "tagDeleted", tagId }`
   - `seq` はタスクとタグで共通の連番とする
5. クライアントは、最後に受け取ったサーバーのタグも保存し、タスクと同じくリベース（サーバーの状態 + 未送信の操作の再実行）でローカルの表示を作り直す
6. **名前の重複**: 2 台がオフラインで同じ名前のタグを作った場合、後からサーバーに届いた `CreateTag` は `TagNameDuplicate` で差し戻される。差し戻された側の端末では、そのタグを付けたタスクからタグが外れて見える（差し戻しの通知で知らせる）
   - 個人用途で、2 台で同時にオフラインのまま同じ名前のタグを作ることはまれなため、自動での統合は行わない

### 画面

7. タグは必ず **色の点 + 名前** で表示し、文字は通常の文字色にする（色だけで区別させない）
8. 色はグラフの指針で検証済みのカテゴリ配色（8 色、ライト・ダーク別の値）を使う

## 検討した代替案

| 案                                                                 | 不採用理由                                                                                                                                        |
| ------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------- |
| タグを文字列としてタスクに直接持たせる                             | 名前の変更をすべてのタスクに反映させる必要があり、オフライン中の変更と競合しやすい。色を持たせる場所もない                                        |
| タグの付け外しを個別の操作（`AddTaskTag` / `RemoveTaskTag`）にする | 2 台で同時に別のタグを付けても両方残る利点があるが、操作の種類が増える。個人用途では同時編集はまれなため、`EditTask` で集合を置き換える方式とする |
| 名前から決まる ID（UUIDv5）にして重複を防ぐ                        | 名前を変更すると、変更前の名前で新しく作ったタグと ID が衝突する                                                                                  |

## 結果

- 良い点: タグの名前・色の変更が 1 か所で済み、すべてのタスクに反映される
- 良い点: 同期の変更ログが種類を持つため、今後ほかの集約（例: 設定）も同期の対象に加えやすい
- 悪い点: 同期の仕組み（変更ログ・クライアントの保存・リベース）に手を入れる範囲が大きい
- 留意点: 削除したタグの ID はタスクに残る。件数が増えて問題になる場合は、定期的に掃除する仕組みを別途検討する
