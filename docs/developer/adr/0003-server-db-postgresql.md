# 0003. サーバー DB に Cloud SQL for PostgreSQL を採用

- ステータス: 提案
- 日付: 2026-10-05

## コンテキスト

- サーバーは GCP（Cloud Run）上で動かし、インフラは Terraform で管理する
- サーバー DB には、集約の永続化、同期用の変更連番（ADR 0002）、Insights 向け集計が求められる
- オフライン同期は自前で実装する方針（ADR 0002）

## 決定

**Cloud SQL for PostgreSQL** を採用する。

- 集約ごとにテーブルを持ち、`owner_id` による行レベルのアクセス制御をアプリケーション層で必ず適用する
- 同期用に変更ログ（変更連番・集約 ID・イベント種別・内容）を保持する
- スキーマ移行はマイグレーションツールで管理する（ツールは実装着手時に選定）
- 接続情報は Secret Manager から取得し、リポジトリ・ログに出力しない

## 検討した代替案

| 案         | 評価                                                                                                                                                                                 |
| ---------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Firestore  | Web・モバイル向けのオフライン SDK を持つ。一方で、データ設計が Firestore の流儀に引っ張られ、共有ドメイン層を介した検証と噛み合いにくい。デスクトップ（Tauri）からの利用にも難がある |
| AlloyDB 等 | 個人用途の規模に対して過剰                                                                                                                                                           |

## 結果

- 良い点: リレーショナルな集約の永続化、連番による同期カーソル、集計クエリを素直に実装できる
- 悪い点: 常時稼働インスタンスの費用が発生する

## 要確認事項

- Cloud SQL の最新の料金体系・最小構成は未確認。個人用途での費用見積もりを行ってから確定する
- 費用が見合わない場合の代替（Firestore 再評価、他のマネージド PostgreSQL 等）を、見積もり結果に応じて検討する
